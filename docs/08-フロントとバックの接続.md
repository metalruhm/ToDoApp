## 1. 目的と完成の定義

**目的**: Next.js画面からGo APIを呼び出し、ToDoアプリとして一通り動かす。CORS・非同期処理・エラー表示を学ぶ。

**完成の定義**:
- [ ] ブラウザから追加・一覧・完了切替・編集・削除がAPI経由で動く（F-01〜F-05）
- [ ] ページを再読み込みしてもデータが残る
- [ ] ローディング中の表示がある
- [ ] APIエラー（400/404/通信失敗）が画面に表示される
- [ ] APIのURLは `NEXT_PUBLIC_API_URL`。`.env.example` を用意した
- [ ] 意図的なコンフリクトを1回体験して解消した

## 2. 用語解説

| 用語 | 意味 |
|------|------|
| CORS | 別オリジン（ポートが違う等）のページからAPIを呼ぶ許可の仕組み |
| オリジン | `スキーム + ホスト + ポート`。`:3000` と `:8080` は別 |
| プリフライト | 本番リクエスト前に自動で送られる `OPTIONS` の確認 |
| `fetch` | ブラウザ標準のHTTP呼び出し |
| `async/await` | 非同期処理を順番に書く記法 |
| `useEffect` | 描画後に副作用（APIの読込み等）を実行する |
| 環境変数 `NEXT_PUBLIC_*` | ブラウザ側のコードに埋め込まれる値。**秘密情報は入れない** |

同じ箇所を2つのブランチで別々に変更し、マージ時にぶつける。
```

git switch main
git switch -c exp/b   # README.md の1行目を「B」に変更してコミット

```
解消手順:
1. `git status` で衝突ファイルを確認
2. ファイル内の `<<<<<<<` `=======` `>>>>>>>` を見て、残す内容に編集
3. マーカー行を**すべて**削除
4. `git add README.md` → `git commit`

練習後はブランチを破棄（`git merge --abort` で中止も可能）。READMEの内容は元に戻す。

### Step 7: マージ
```

```

## 4. ヒント
- `fetch` のエラーは2種類: ネットワーク失敗（例外）と、HTTPエラー（`res.ok === false`）
- 連打対策: 送信中はボタンを無効化
- エラー表示は `alert` でなく画面内に表示
- 楽観的更新（先に画面を変える）は発展課題

## 5. つまずきやすい点
- `blocked by CORS policy` → オリジン不一致/ヘッダー不足。`ALLOWED_ORIGIN` を確認
- `.env.local` 変更後に反映されない → `npm run dev` を再起動
- `undefined/todos` にアクセスしている → `NEXT_PUBLIC_` が付いていない
- 開発モードで `useEffect` が2回走る → React StrictModeの仕様（開発時のみ）
- `localhost` と `127.0.0.1` は別オリジン

<summary>Step 2 の答え: Go側のCORSミドルウェア（internal/handler/cors.go）</summary>

```go
package handler

import "net/http"

// CORS は許可したオリジンからのブラウザアクセスを通すミドルウェア。
func CORS(allowedOrigin string, next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Access-Control-Allow-Origin", allowedOrigin)
		w.Header().Set("Access-Control-Allow-Methods", "GET, POST, PATCH, DELETE, OPTIONS")
		w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		w.Header().Set("Vary", "Origin")

		if r.Method == http.MethodOptions { // プリフライト
			w.WriteHeader(http.StatusNoContent)
			return
		}
		next.ServeHTTP(w, r)
	})
}
```

`main.go` での使い方
```go
allowed := os.Getenv("ALLOWED_ORIGIN")
if allowed == "" {
	allowed = "http://localhost:3000"
}
log.Fatal(http.ListenAndServe(":"+port, handler.CORS(allowed, mux)))
```
- ミドルウェア＝「ハンドラーを受け取って、ハンドラーを返す関数」。前後に共通処理を挟める
- `OPTIONS` は本番のリクエストの前にブラウザが自動で送る確認

テスト（`cors_test.go`）
```go
package handler

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestCORS(t *testing.T) {
	next := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) { w.WriteHeader(200) })
	h := CORS("http://localhost:3000", next)

	t.Run("ヘッダーが付く", func(t *testing.T) {
		rec := httptest.NewRecorder()
		h.ServeHTTP(rec, httptest.NewRequest("GET", "/", nil))
		if got := rec.Header().Get("Access-Control-Allow-Origin"); got != "http://localhost:3000" {
			t.Errorf("got %q", got)
		}
	})
	t.Run("OPTIONSは204", func(t *testing.T) {
		rec := httptest.NewRecorder()
		h.ServeHTTP(rec, httptest.NewRequest("OPTIONS", "/todos", nil))
		if rec.Code != 204 {
			t.Errorf("got %d", rec.Code)
		}
	})
}
```

<summary>Step 3 の答え: APIクライアント（frontend/src/lib/api.ts）</summary>

```ts
import type { Todo } from "@/types/todo";

const BASE_URL = process.env.NEXT_PUBLIC_API_URL ?? "http://localhost:8080";

async function request<T>(path: string, init?: RequestInit): Promise<T> {
  let res: Response;
  try {
    res = await fetch(`${BASE_URL}${path}`, {
      ...init,
      headers: { "Content-Type": "application/json", ...init?.headers },
    });
  } catch {
    // ネットワーク失敗（API停止など）
    throw new Error("サーバーに接続できません");
  }

  if (!res.ok) {
    // HTTPエラー: { error: { code, message } } を読む
    const body = await res.json().catch(() => null);
    throw new Error(body?.error?.message ?? `エラーが発生しました (${res.status})`);
  }
  if (res.status === 204) return undefined as T; // 本文なし
  return res.json() as Promise<T>;
}

export type TodoStatus = "all" | "active" | "done";

export const listTodos = (status: TodoStatus = "all") =>
  request<Todo[]>(`/todos?status=${status}`);

export const createTodo = (title: string) =>
  request<Todo>("/todos", { method: "POST", body: JSON.stringify({ title }) });

export const updateTodo = (id: number, patch: { title?: string; done?: boolean }) =>
  request<Todo>(`/todos/${id}`, { method: "PATCH", body: JSON.stringify(patch) });

export const deleteTodo = (id: number) =>
  request<void>(`/todos/${id}`, { method: "DELETE" });
```

`frontend/.env.local`（コミットしない）と `frontend/.env.example`（コミットする）
```
NEXT_PUBLIC_API_URL=http://localhost:8080
```
`create-next-app` が作る `.gitignore` に `.env*` が含まれている場合、`.env.example` まで無視される。`git check-ignore -v frontend/.env.example` で確認し、無視されるなら `.gitignore` に `!.env.example` を追加する。

<summary>Step 4 の答え: 画面をAPIに接続（src/app/page.tsx）</summary>

```tsx
"use client";

import { useEffect, useState } from "react";
import type { Todo } from "@/types/todo";
import { TodoForm } from "@/components/TodoForm";
import { TodoList } from "@/components/TodoList";
import { createTodo, deleteTodo, listTodos, updateTodo } from "@/lib/api";

export default function Home() {
  const [todos, setTodos] = useState<Todo[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    listTodos()
      .then(setTodos)
      .catch((e: Error) => setError(e.message))
      .finally(() => setLoading(false));
  }, []); // [] = 最初の1回だけ実行

  // 共通: 成功したらエラーを消し、失敗したらメッセージを出す
  async function run(action: () => Promise<void>) {
    setError("");
    try {
      await action();
    } catch (e) {
      setError(e instanceof Error ? e.message : "エラーが発生しました");
    }
  }

  const addTodo = (title: string) =>
    run(async () => {
      const created = await createTodo(title);
      setTodos((prev) => [created, ...prev]);
    });

  const toggleTodo = (id: number) =>
    run(async () => {
      const target = todos.find((t) => t.id === id);
      if (!target) return;
      const updated = await updateTodo(id, { done: !target.done });
      setTodos((prev) => prev.map((t) => (t.id === id ? updated : t)));
    });

  const editTodo = (id: number, title: string) =>
    run(async () => {
      const updated = await updateTodo(id, { title });
      setTodos((prev) => prev.map((t) => (t.id === id ? updated : t)));
    });

  const removeTodo = (id: number) =>
    run(async () => {
      await deleteTodo(id);
      setTodos((prev) => prev.filter((t) => t.id !== id));
    });

  return (
    <main>
      <h1>ToDo</h1>
      <TodoForm onAdd={addTodo} />
      {error && <p role="alert">{error}</p>}
      {loading ? (
        <p>読み込み中…</p>
      ) : (
        <TodoList todos={todos} onToggle={toggleTodo} onDelete={removeTodo} onEdit={editTodo} />
      )}
    </main>
  );
}
```
- `TodoForm` の `onAdd` は `Promise` を返すので、型を `(title: string) => void | Promise<void>` にしておく
- サーバーが400を返した場合のメッセージ（例:「タイトルは1〜100文字…」）は `error` に入って表示される
- 連打対策は Section 9 で扱う
</details>

<details>
<summary>Step 6 の答え: コンフリクト体験のコマンド全体</summary>

```
git switch main
git switch -c exp/a
# README.md の1行目を「A」に変更
git add README.md && git commit -m "exp: change A"

git switch main
git switch -c exp/b
# README.md の1行目を「B」に変更
git add README.md && git commit -m "exp: change B"

git merge exp/a
# → CONFLICT (content): Merge conflict in README.md
```
README.md の中身:
```
<<<<<<< HEAD
B
=======
A
>>>>>>> exp/a
```
解消:
```
# 1. 残したい内容に編集（例: "A and B"）。<<<<<<<, =======, >>>>>>> の3行を必ず消す
git add README.md
git commit            # マージコミット。メッセージはそのままでOK
```
中止したいとき: `git merge --abort`

後片付け:
```
git switch main
git branch -D exp/a exp/b
# README.md が実験前の状態か git diff / git log で確認。main に不要なマージが入ったら、練習はブランチ exp/b 上でやること
```
※ 練習用のため、`main` ではなく `exp/b` の上でマージすれば `main` は汚れない。
</details>
