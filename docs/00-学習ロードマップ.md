# ToDoアプリ 学習ロードマップ（Next.js + Go / AI駆動開発 / Git練習）

## 0. このロードマップの目的

- Next.js（フロント）と Go（バックエンドAPI）でToDoアプリを作る
- AI駆動開発の流れを体験する
- **Gitの基本操作を、毎セクション繰り返して身につける**

## 1. 基本の進め方（全セクション共通サイクル）

```
① ブランチを切る      git switch -c docs/xx-題名
② AIにドキュメント作成を依頼（設計・仕様・手順）
③ 自分でレビュー（修正指示 or 自分で直す）
④ ドキュメントをコミット   docs: ... 
⑤ 実装ブランチを切る    git switch -c feat/xx-題名
⑥ ドキュメントを見ながら自分でコーディング（詰まったらAIに質問）
⑦ 動作確認 → 小さくコミット   feat: ...
⑧ main にマージ（またはPR）→ ブランチ削除
⑨ ふりかえり（学んだこと・つまずきを docs/learning-log.md に追記）
```

ポイント:
- **AIはドキュメントを書く役、コードは自分で書く**（理解のため）。コード生成をAIに頼むのは「詰まったとき」「レビューしてほしいとき」に限定する
- レビュー観点: 目的に合っているか / 分からない用語がないか / 作業が1コミット単位に分割されているか / 過剰に複雑でないか
- 1セクション = ドキュメントのコミット1〜2個 + 実装のコミット数個、が目安

### コミットメッセージ規約（Conventional Commits）

| 種類 | 用途 | 例 |
|------|------|----|
| docs | ドキュメント | `docs: タスクAPIの仕様書を追加` |
| feat | 機能追加 | `feat: タスク一覧取得APIを追加` |
| fix | バグ修正 | `fix: 空タイトルを登録できる問題を修正` |
| refactor | 挙動を変えない整理 | `refactor: ハンドラーを分割` |
| test | テスト | `test: タスク作成のテストを追加` |
| chore | 設定・依存関係 | `chore: gitignoreを追加` |

### ブランチ命名

`docs/セクション番号-題名` / `feat/セクション番号-題名` / `fix/題名`

### AIへの依頼テンプレート（ドキュメント作成）

```
セクション「◯◯」のドキュメントを docs/ に作って。
- 目的 / 完成の定義 / 手順（コミット単位に分割）/ 用語解説 / つまずきやすい点
- 各Stepの答え（コード・コマンド）は、ファイル末尾の「付録」にまとめて（折りたたみ形式で）
```

## 3. セクション一覧（チェックリスト）

### Section 1: 環境構築とGit入門

- [ ] コンフリクトを解消できる

- [ ] `stash` で作業を一時退避できる
- [ ] `rebase` と `merge` の違いを説明できる
- [ ] Pull Request を作ってレビューできる
- [ ] 機密情報を誤ってコミットした時の対処を説明できる
- [ ] `tag` でバージョンを切れる

## 5. AI駆動開発のコツ

1. **指示は具体的に**: 目的・制約・出力形式（ファイル名）を書く
2. **小さく頼む**: 1セクション・1ドキュメントずつ
3. **必ず読む**: AIの出力は鵜呑みにせず、分からない箇所は質問する
4. **コンテキストを渡す**: `docs/` の内容を参照させる（`CLAUDE.md` に技術スタックと規約を書いておくと良い）
5. **レビューをコミットで残す**: 「AIの初稿」と「自分の修正後」を別コミットにすると、差分でレビュー力を確認できる
