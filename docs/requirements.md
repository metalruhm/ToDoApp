# 要件定義書（ToDoアプリ）

> ステータス: **自分レビュー済み**
> レビュー時は、気になる箇所に `<!-- REVIEW: ... -->` を書くか直接修正し、初稿と修正後を別コミットにする。

## 1. 目的

- Next.js と Go を使った学習用ToDoアプリを作る
- 目的は「実用性」より「Web開発の一連の流れ（設計 → API → UI → テスト → デプロイ）とGit運用の習得」

## 2. 想定ユーザー・利用シーン

- 利用者: 自分（学習者）。Section 10 までは**単一ユーザー**
- 利用シーン: PCブラウザで、やることを登録・確認・完了・削除する

## 3. スコープ

| 区分 | 内容 |
|------|------|
| 対象（MVP） | タスクの追加・一覧・完了切替・編集・削除 |
| 対象（後半） | フィルタ表示、永続化（DB）、テスト、Docker/CI、デプロイ |
| 発展 | ユーザー認証、ユーザー別ToDo（Section 10） |
| 対象外 | 期限通知、共有、タグ、並び替えのドラッグ操作、モバイルアプリ、多言語対応 |

## 4. 機能要件

優先度: **M** = 必須（MVP）、**S** = あれば良い、**C** = 発展

| ID | 機能 | 内容 | 優先度 |
|----|------|------|--------|
| F-01 | タスク追加 | タイトルを入力して追加できる | M |
| F-02 | タスク一覧 | 登録済みタスクを作成日時の新しい順に表示する | M |
| F-03 | 完了切替 | タスクの完了/未完了を切り替えられる | M |
| F-04 | タスク編集 | タイトルを変更できる | M |
| F-05 | タスク削除 | タスクを削除できる | M |
| F-06 | フィルタ | 全て / 未完了 / 完了 で絞り込める | S |
| F-07 | 入力検証 | 空のタイトルは登録できず、エラーが表示される | M |
| F-08 | 永続化 | リロードやサーバー再起動後もデータが残る | M（Section 6〜） |
| F-09 | ユーザー認証 | ログインしたユーザーのタスクのみ扱える | C |

### 受け入れ条件（F-01〜F-07）

- F-01: タイトルを入力して追加すると、一覧の先頭に表示される。追加後に入力欄は空になる
- F-02: タスクが0件のとき「タスクがありません」と表示する
- F-03: チェック操作で完了状態が切り替わり、完了タスクは見た目で区別できる（取り消し線など）
- F-04: 編集して保存すると一覧に反映される。空にして保存はできない
- F-05: 削除するとタスクが一覧から消える（誤操作防止の確認は S）
- F-06: 選択したフィルタに該当するタスクだけが表示される
- F-07: タイトルが空（空白のみを含む）の場合は登録を拒否する。上限は100文字とする

## 5. 非機能要件

| 項目 | 要件 |
|------|------|
| 性能 | 操作に対する応答は通常1秒以内（ローカル環境） |
| 保守性 | フロント/バックを分離し、APIは `docs/api-spec.md` に従う。Goはストア層をインターフェース化する |
| テスト | バックエンドの主要ロジックに単体テストを書く（Section 5） |
| セキュリティ | 秘密情報は `.env` に置きコミットしない。入力値はサーバー側でも検証する。認証導入時はパスワードをハッシュ化する |
| 可搬性 | `docker compose up` で起動できる（Section 11） |

## 6. 技術スタック（案）

| 領域 | 採用 |
|------|------|
| フロント | Next.js（App Router）, TypeScript, Tailwind CSS |
| バックエンド | Go（標準 `net/http` から開始） |
| DB | SQLite（学習用）。必要に応じてPostgreSQL |
| 開発手法 | AIがドキュメント作成 → 自分がレビュー → 自分がコーディング |
| 管理 | Git / GitHub、Conventional Commits |

## 7. 画面（概要）

単一画面で完結させる。

```
+--------------------------------------+
| ToDo                                 |
| [ 新しいタスクを入力        ] [追加]  |
| (エラーメッセージ表示欄)              |
| [全て] [未完了] [完了]                |
| ------------------------------------ |
| [ ] 牛乳を買う          [編集][削除]  |
| [x] レポート提出        [編集][削除]  |
+--------------------------------------+
```

## 8. 前提・制約

- 学習が目的のため、品質より理解を優先する。コードは原則として自分で書く
- 認証導入までは、公開環境にデプロイしない（誰でも触れてしまうため）

## 9. 未決事項（レビューで決めること）

1. タイトルの最大文字数は100でよいか
    - 問題ない 
2. 削除時の確認ダイアログは必要か
    - 不要
3. 完了タスクは一覧の下に移動するか、位置を保つか
    - 移動する
4. 「説明文」「期限」の項目をMVPに含めるか（現状は含めない）
    - 含めない
5. DBはSQLiteで始めてよいか
    - 問題ない
